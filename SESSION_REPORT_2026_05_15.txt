CHANGE 1: New file — backend/src/services/pii.redactor.ts (62 lines)

  Purpose: Tokenize patient-identifiable data before any LLM API call.
  Required by DPDP Act 2023 §16 (cross-border data transfer with pseudonymization).

  PII patterns covered (with regex):
    PHONE      — Indian mobile numbers (6-9 prefix, 10 digits)
    EMAIL      — Standard email pattern
    DOB        — Date formats: DD/MM/YYYY, YYYY-MM-DD, DD-MM-YY
    MRN        — Medical record number patterns (MRN: XXXX)
    PATIENT_ID — Standard clinical trial subject ID prefixes (P-, PT-, SUB-, SUBJ-, PAT-)
    AADHAAR    — 12-digit Aadhaar format (XXXX XXXX XXXX)
    PAN        — Indian PAN card format (AAAAA9999A)

  PIIRedactor class:
    - redact(text: string) → string
      Replaces each PII match with a token: [PHONE_1], [EMAIL_2], etc.
      Maintains internal Map<token, original> for restoration.
      Same value always gets the same token (idempotent within a session).
    - restore(text: string) → string
      Substitutes all tokens back to originals for display.
    - hasRedactions() → boolean
    - redactionCount() → number

  sanitizeEdcSummary() function:
    Accepts { patientCount, entryCount, query } and returns a safe aggregate
    string — never individual patient records.
    This is what analyzeEdcData() now sends to the LLM instead of raw DB rows.

  Integration: Applied automatically in agent.orchestrator.ts for tabs
  with requiresPIIRedaction: true (match, edc). The original query is stored
  in the DB unredacted (local storage); only the redacted version leaves the server.

CHANGE 2: Prisma schema — AgentAuditLog model added

  Model definition added to backend/prisma/schema.prisma:

    model AgentAuditLog {
      id         String   @id @default(uuid())
      userId     String   @map("user_id")
      sessionId  String?  @map("session_id")
      action     String   @db.VarChar(50)   -- PLAN|TOOL_CALL|SYNTHESIS|ARTIFACT|PII_REDACTED|ERROR
      toolName   String?  @map("tool_name") @db.VarChar(100)
      queryHash  String?  @map("query_hash") @db.VarChar(16)  -- first 16 chars SHA-256
      status     String   @db.VarChar(20)   -- ok | error
      durationMs Int?     @map("duration_ms")
      meta       Json?                       -- structured extras (count, size, artifactId, etc.)
      createdAt  DateTime @default(now()) @map("created_at")

      @@index([userId])
      @@index([sessionId])
      @@index([createdAt])
      @@map("agent_audit_logs")
    }

  Design decisions:
    - No userId FK relation → orphan-safe, audit log survives user deletion
    - sessionId is nullable → pre-session errors can still be logged
    - queryHash (SHA-256 first 16 chars) → allows correlation without exposing PHI
    - meta: Json → flexible structured data per action type
    - createdAt index → efficient range queries for compliance exports
    - NO update/delete operations on this table (append-only by convention)

CHANGE 3: Major update — backend/src/services/agent.orchestrator.ts (497 lines)

  Three improvements added to the existing 385-line orchestrator:

  3a. Prompt Caching (Anthropic API)

    When ANTHROPIC_API_KEY is present, the callLLM() function now:
    - Sets header: 'anthropic-beta': 'prompt-caching-2024-07-31'
    - Wraps system message as a content block with cache_control:
        system: [{ type: 'text', text: systemText, cache_control: { type: 'ephemeral' } }]

    Effect: The system prompt (identical for all requests within a tab) is cached
    at Anthropic's servers for 5 minutes. Cache reads cost $0.30/MTok vs $3/MTok
    for Sonnet 4.6 — a 10× cost reduction on the largest repeated token block.

    The Perplexity path is unchanged (no caching API available).

  3b. PIIRedactor integration

    Tab configs now have a requiresPIIRedaction: boolean field:
      research:   false  (no patient data)
      match:      true   (patient descriptions)
      regulatory: false  (regulatory queries)
      protocol:   false  (protocol design)
      edc:        true   (EDC queries may reference patient context)
      analysis:   false  (aggregate data only)

    In runAgent(), before any LLM call:
      const redactor = new PIIRedactor();
      const safeQuery = config.requiresPIIRedaction ? redactor.redact(query) : query;

    If redactions occurred, a PII_REDACTED audit log entry is written.
    The original query is persisted to agent_messages (local Postgres, never sent externally).
    The safeQuery (redacted) is used in all LLM calls.

    The edc tab's analyzeEdcData() also updated: now uses sanitizeEdcSummary()
    to produce an aggregate summary instead of passing raw DB rows to the LLM.

  3c. Audit trail — writeAudit() function

    Internal helper:
      async function writeAudit(opts: { userId, sessionId?, action, toolName?,
        queryHash?, status, durationMs?, meta? }): Promise<void>

    Called at every significant step in runAgent():
      - After PII redaction (if any)   → action: 'PII_REDACTED'
      - After planning LLM call         → action: 'PLAN'
      - After each tool execution       → action: 'TOOL_CALL'
      - After synthesis LLM call        → action: 'SYNTHESIS'
      - After artifact creation         → action: 'ARTIFACT'
      - On any error                    → action: 'ERROR'

    Failure behavior: writeAudit() wraps all Prisma calls in try/catch.
    Audit write failures are silently swallowed — they must never crash the agent run.
    This is intentional: an audit write failure is a monitoring alert, not a 503.

  3d. hashInput() utility

    import { createHash } from 'crypto';
    function hashInput(text: string): string {
      return createHash('sha256').update(text).digest('hex').slice(0, 16);
    }

    Used to produce queryHash field in audit logs. SHA-256 of the query text,
    first 16 hex characters. Allows log correlation without storing PHI.
