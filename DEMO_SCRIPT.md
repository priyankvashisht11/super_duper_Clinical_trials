## Demo: The Conversation (3 minutes)

### Step 1: Greeting (20 seconds)

**Screen**: AI agent appears with greeting

**AI**: "Hi! I'm your AI Sample Size Calculator. I'll help you determine the optimal sample size through a quick conversation.

Study Details I Have:
• Indication: Type 2 Diabetes Mellitus
• Phase: Phase III
• Design: Parallel Group

Let's start: Is your primary endpoint continuous or binary?"

**Narrator**: "Notice how the AI already knows your study details from other sections of the protocol. It's context-aware."

### Step 2: Endpoint Type (20 seconds)

**Screen**: User types response

**User types**: "Binary - it's response rate"

**AI**: "Great! Response rate is a binary endpoint. What response rates do you expect in each group? For example: 'Control 30%, Treatment 50%'"

**Narrator**: "The AI provides examples to help users understand what information is needed."

### Step 3: Effect Size (20 seconds)

**User types**: "We expect control group to have 40% response rate and treatment group 60%"

**AI**: "Perfect! A 20% absolute difference. That's clinically meaningful. Now, what statistical power and significance level would you like? Most trials use 80% power with 0.05 alpha."

**Narrator**: "The AI validates the input and provides context about standard values."

### Step 4: Statistical Parameters (20 seconds)

**User types**: "Let's go with standard - 80% power and 0.05 alpha"

**AI**: "Excellent choice. Finally, what dropout rate do you anticipate? Phase III trials typically see 15-20% dropout."

**Narrator**: "The AI provides phase-appropriate guidance."

### Step 5: Dropout Rate (20 seconds)

**User types**: "About 15%"

**AI**: "Got it! Let me calculate the optimal sample size for you..."

**Screen**: Loading indicator for 2 seconds

**Narrator**: "The AI performs the calculation using validated statistical formulas."

### Step 6: Results (40 seconds)

**Screen**: Results appear in beautiful cards

**AI**: "✅ Calculation Complete!

┌──────────────────────────────────────┐
│  Total Sample Size: 194              │
│  Per Arm: 97                         │
│  Dropout Rate: 15%                   │
└──────────────────────────────────────┘

Justification:
Sample size calculated using two-proportion formula for binary endpoint. With 80% power to detect a difference from 40% to 60% (20% absolute difference) at α=0.05 (two-sided), we need 84 participants per arm. Accounting for 15% dropout rate, total sample size is 194 (97 per arm).

Power Analysis:
This study is powered at 80% to detect a 20% absolute difference in response rates with 0.05 significance level (two-sided). The calculation assumes equal allocation to treatment arms and uses the standard normal approximation for proportions."

**Narrator**: "The AI provides not just numbers, but complete documentation including justification and power analysis - everything needed for regulatory submissions."

**Screen**: User clicks "Apply to Protocol" button

**Narrator**: "With one click, all fields are automatically filled..."

**Screen**: Show fields being populated

**Narrator**: "...the protocol is saved..."

**Screen**: Show save confirmation

## Demo Tips

### For Live Demos:

1. **Prepare the Protocol**
   - Have a protocol with metadata filled
   - Use a realistic indication (e.g., Type 2 Diabetes)
   - Set phase to Phase III for best demo

2. **Practice the Conversation**
   - Know your responses ahead of time
   - Type naturally (not too fast)
   - Pause to let AI respond

3. **Highlight Key Moments**
   - Point out context awareness
   - Emphasize the educational aspect
   - Show the one-click application
   - Demonstrate the auto-fill

4. **Handle Questions**
   - Be ready to explain formulas
   - Show the documentation
   - Demonstrate recalculation
   - Show sensitivity analysis

### For Video Demos:

1. **Use Screen Recording**
   - High quality (1080p minimum)
   - Clear audio narration
   - Smooth transitions
   - Professional editing

2. **Add Visual Effects**
   - Highlight important elements
   - Zoom in on key features
   - Use callouts for emphasis
   - Add background music (subtle)

3. **Keep It Engaging**
   - Vary the pace
   - Use real-world examples
   - Show actual user reactions
   - Include testimonials

### For Sales Presentations:

1. **Start with Pain Points**
   - Show the problem first
   - Make it relatable
   - Build empathy

2. **Demonstrate Value**
   - Show time savings
   - Highlight ease of use
   - Emphasize accuracy

3. **Close with Impact**
   - Show metrics
   - Share testimonials
   - Offer trial
